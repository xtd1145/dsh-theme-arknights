# 设计语言

本文说明三套阵营**是什么颜色、为什么是这个值、落在哪个界面角色上**，以及进阶版的终端界面层如何组成。安装、开关与工程验证见 [README](../README.md)。

---

## 一、一套版式，三种性格

三套阵营共用同一份几何：同一个间距、同一套组件、同一种直角。差异落在四个维度上：

1. **纸与墨**（背景、面板、正文）——决定「这是什么地方」
2. **强调色与信号色**（按钮、选中、焦点、状态）——决定「谁在说话」
3. **标题字族与字距**——决定「这个空间的气质」
4. **氛围纹理**——决定「这台终端在什么环境里运行」

这条约束是刻意的：如果三套皮肤连布局都不同，它们就不是「一个主题的三套配色」，而是三个主题。共用版式换来的是**切换时页面不跳动**。

强调色只用于「需要被看见的那一处」，不铺大面积。大面积铺色会让三套阵营的对比度验算失去意义：底色一旦带强调色，所有前景色的验算前提都变了。

在**进阶版**里，三套阵营共用同一套终端结构：

- 侧栏顶部是 PRTS 铭牌（扇区、阵营字标、链路状态、信号格、频道）
- 工作区列表变成编号的「终端作战位置」
- 空状态的工作区选择器变成部署面板，菜单打开时再出现部署控制抬头
- 输入区是任务简报通道，顶栏是频道标注，空状态底部是作战记录带

**通用适配**只换颜色、字体和细节，不注入终端 DOM，也不改变应用骨架。

## 二、色板

### 2.1 令牌：`--edge-*`

六组变量（3 阵营 × 明暗）声明在 `src/styles/faction.css` 的 `<body>` 规则里。`theme.css` 的功能样式、终端层派生量和三套氛围纹理都只读这些变量；令牌层再把 DSH 的每个语义令牌（`--dsw-alias-*`）覆盖成 `var(--edge-*)`。

核心角色：

| 角色 | 令牌 | 用途 |
| --- | --- | --- |
| 纸底 | `--edge-paper` | 页面底色、反白文字 |
| 面板 | `--edge-panel` | 卡片、侧栏、部署面板 |
| 浮层 | `--edge-overlay` | 菜单、弹窗 |
| 沉底块 | `--edge-soft` | 铭牌底、次级区块 |
| 细线 / 重线 | `--edge-line` / `--edge-line-2` | 分隔、边界、选中轮廓 |
| 正文 / 次要文字 | `--edge-ink` / `--edge-ink-2` | 正文、HUD 标注、说明 |
| 强调 | `--edge-accent` | 按钮、选中、焦点、扇区号 |
| 强调（纸面档） | `--edge-accent-onpaper` | 亮色纸面上的文字强调 |
| 强调深档 | `--edge-accent-deep` | 悬停、按下、实心按钮 |
| 信号 | `--edge-signal` | 状态灯、莱茵的橙色点缀 |
| 状态文字 | `--edge-status-light` / `--edge-status-dark` | 回合标签及扫光亮带 |

`--edge-accent-rgb` 必须与 `--edge-accent` 的 hex 分量一致：所有半透明色块都写成 `rgba(var(--edge-accent-rgb), α)`。当前三套**亮色档本身已经压得足够深**，所以 `--edge-accent` 与 `--edge-accent-onpaper` 取同一个值；暗色档保留一个较深的 `--edge-accent-onpaper`，供需要「纸面强调」语义的地方使用。测试会在两种模式下各取该用的那一档，不会拿错档算出一堆假失败。

| 沉底块 | `#e6eaee` | `#171a1d` |
| 细线 / 重线 | `#d5dbe1` / `#b6bfc8` | `#24282c` / `#383e45` |
| 正文 / 次要 | `#0b0d0f` / `#4b545c` | `#f2f5f7` / `#98a2ab` |
| **强调** | `#1a6fa8` | `#4fb3e8` |

亮色底不用纯白：`#f2f4f6` 带一点冷灰，是「屏幕上的纸」而不是「屏幕」。暗色底 `#08090a` 接近纯黑，用来承载细线和低透明度纹理，避免深灰界面常见的雾感。

### 2.5 语义状态色

错误、成功、警告不参与阵营切换，但**每一套阵营各有一组**：同一个红要在暖白（莱茵）和冷白（罗德岛）上都过 AA，深度不能照抄。

| 角色 | 罗德岛·亮 | 拉特兰·亮 | 莱茵·亮 | 三套·暗 |
| --- | --- | --- | --- | --- |
| 错误 | `#b42318` | `#b42318` | `#a32318` | `#ff6b61` |
| 成功 | `#197c4a` | `#0f6b3f` | `#1a6b46` | `#4fbf5c` |
| 警告 | `#9a5b00` | `#8a5300` | `#8a5a00` | `#ffb700` |

暗色模式的三套共用一组更亮的语义色：近黑纸面上，亮色的可读性余量充足，没必要为每个阵营各做一套。

## 三、对比度量算

每个角色都对它**实际落在的表面**验算，不达标则测试失败（`test/palette-contrast.test.js`，194 项断言）。

验算的组数不是 6 而是 12：三套阵营 × 明暗 × 两个档位。第三档「莱茵终端版」叠在阵营之上，测试按运行时的层叠顺序把两层变量表合并（阵营组 ∪ `lab.css` 档位组）再算——只验阵营那一份纸面，验的是「陶瓷档实际不会用到的那个底色」。

| 角色 | 门槛 | 说明 |
| --- | --- | --- |
| 正文 on `paper` / `panel` | **AAA 7:1** | 一套界面主题的正文没有理由停在及格线 |
| 次要文字 on `paper` / `panel` | AA 4.5:1 | |
| 强调色作为文字 on `paper` / `panel` | AA 4.5:1 | 亮色模式读 `accent-onpaper`，暗色读 `accent` |
| 实心强调底上的字 | AA 4.5:1 | 前景固定用 `--edge-paper` |
| 回合状态文字及其亮带 | AA 4.5:1 × 两种底色 | 扫光亮带会压在字形上，所以两种底色都要过 |
| 语义状态色 on `paper` | AA 4.5:1 | 陶瓷档另测它自己的 `error/success/warn` |
| 细线 on `paper` | ≥ 1.12:1 | 装饰性下限：低于此形同不存在 |
| 重线 on `paper` | ≥ 1.35:1 | 边界要看得出 |
| 三套阵营的强调色 | 两两不同 | 否则「三套」没有意义 |
| 档位与阵营的分工 | accent 相同、paper 不同 | 莱茵终端档不许改颜色，只许改材质 |

另外两项机械校验：

- `--edge-accent-rgb` 必须与 `--edge-accent` 的 hex 分量一致——半透明色块都依赖它。
- 六组阵营变量集 + 两组档位变量集必须各自完整，且每个阵营的字体 / 字距只在亮色组声明一次、由暗色组继承——漏掉的表现是「切到暗色后掉回默认阵营的色板」或「字体漂移」。

> **装饰性表面的对比度描述的是「有多抢眼」，不是可读性。** 纹理、水印永远在所有内容之下，它们的数值用来控制干扰强度。

## 四、机制：切阵营只是一个 class

这是整套主题能「快速切换」的根本原因。

**第一步：令牌层不写色值，只写变量引用。**

DSH 的每个语义令牌（`--dsw-alias-bg-base` 等）被 `theme.overrideTokens` 覆盖成：

```js
'--dsw-alias-bg-base': { light: 'var(--edge-paper)', dark: 'var(--edge-paper)' }
```

light 与 dark 给同一个 `var`：这个变量自己在样式表里按 `[data-ds-dark-theme]` 分档，所以令牌层不需要知道明暗。

**第二步：`--edge-*` 按 `<body>` 的 class 分组声明。**

```css
body.theme-arknights-themed                     { --edge-paper: #f2f4f6; --edge-accent: #1a6fa8; }  /* 罗德岛·亮 */
body.theme-arknights-themed[data-ds-dark-theme] { --edge-paper: #08090a; --edge-accent: #4fb3e8; }  /* 罗德岛·暗 */
body.theme-arknights-themed.theme-arknights-laterano { --edge-paper: #eceef2; --edge-accent: #1a3fd0; }  /* 拉特兰·亮 */
… 共六组
```

**第三步：关键事实 —— 应用是把令牌写成 `<body>` 的行内样式。**

行内样式里的 `var()` 引用同元素上由样式表声明的自定义属性，是合法且同批解析的。于是：

> 给 `<body>` 加减一个 class → `--edge-*` 重新解析 → 行内样式里的 `var(--edge-*)` 跟着变 → 整份界面换色。

**不重新注册令牌层、不重算应用侧样式、无 JS 重绘、无 canvas 重画。**

进阶版的氛围纹理与终端节点也读同一批变量；切阵营时终端层只更新铭牌、频道与字标文本，不重建节点。

## 五、几何语言

明日方舟式的辨识度主要来自四组几何动作，它们在三套阵营里完全一致：

| 动作 | 做法 | 落点 |
| --- | --- | --- |
| **全直角 + 斜切角** | 面板、按钮、菜单统一 `border-radius: 0`，右下角 `clip-path` 切 8–14px | 部署面板、输入卡、菜单、卡片 |
| **HUD 标注** | 6–9px 等宽大写英文，字距 `0.14–0.3em`，常带编号 / 状态灯 / 十字准星 | 铭牌、抬头、顶栏、页脚、输入卡 |
| **扇区编号** | `01`…`N` 等宽编号 + 填充式选中行 + 右下角小切角 | 工作区列表、菜单项、hero、页脚 |
| **细双线** | 一根发丝线 + 一段强调色短线，用于分区与收边 | 抬头、侧栏、部署面板、页脚 |

终端各区域的映射：

| DSH 区域 | 终端语义 | 关键装饰 |
| --- | --- | --- |
| 侧栏 logo 下方 | PRTS 铭牌 | 扇区号、`SECTOR COMMAND`、阵营字标、`LINK ESTABLISHED`、信号格、频道 |
| 工作区列表上方 | 终端作战位置抬头 | `PRTS // DEPLOYMENT`、实时扇区数、`TERMINAL DEPLOYMENT POSITION` |
| 工作区行 | 作战位置槽位 | `01`…`N` 编号、选中填充、切角、反白图标与标题；「未分组」桶不编号 |
| 空状态 | 部署图纸 | 四角括号、巨大幽灵扇区号、`SECTOR xx // TERMINAL DEPLOYMENT` |
| 工作区选择器 | 部署面板 | 左上斜切标签、右上 `SECTOR xx // READY`、切角边框 |
| 工作区菜单 | 部署控制面板 | `PRTS // DEPLOYMENT CONTROL`、位置数、编号菜单项、选中勾 |
| 输入卡 | 任务简报通道 | `INPUT CHANNEL // MISSION BRIEF`、内嵌左轨、网格底纹、右下角括号 |
| 顶栏（空状态） | 指挥频道 | 左侧频道名、右侧 `SIGNAL 04 · LINK STABLE` |
| 空状态底部 | 作战记录带 | `PRTS // OPERATIONS LEDGER`、扇区胶囊、频道与链路状态 |

幽灵扇区号是 `hero-stack` 的 `::before`，内容来自 `data-ak-sector`：字号 `clamp(120px, 15vw, 236px)`，填充极低透明度的强调色并描边。拉特兰换成衬线字族，莱茵取消描边、只留淡淡填充。

## 六、三套氛围纹理

纹理全部由**内联 SVG 遮罩**绘制：SVG 只写白色形状，CSS 用 `mask-image` 取 alpha，再用 `background-color: var(--edge-accent)` 上色。同一张形状因此可以跟随强调色、明暗和阵营变化，不必为 6 种组合准备 6 张图。

| 阵营 | 遮罩形状 | 透明度 | 叠加 |
| --- | --- | --- | --- |
| 罗德岛 | 90 / 450px 网格；轨道圆环（半径 170 / 330 / 470）；节点拓扑与连线；通讯弧线；四角刻度 | `0.62` | 暗色 `screen`，亮色 `multiply` |
| 拉特兰 | 36 / 180px 图纸网格；同心圆（半径 90 / 150 / 230 / 300）；十字准线；斜切多边形；坐标刻度与弧线 | `0.42` | 同上 |
| 莱茵生命 | 72 / 360px 网格；全屏 X 对角线；旋转 ±24° 的椭圆 ∞ 结构；十字准星；矩形标记；极细分度 | `0.34` | 同上 |

三层叠加构成完整气氛：

1. **遮罩层**（`frame::before`）：按阵营切换的几何形状，颜色读强调色。
2. **静态气氛层**（`frame::after`）：两处强调色径向光晕 + 点阵 + 一条 180px 的内联噪声 SVG 纸张颗粒。莱茵的点阵换成橙色，信号感只出现在这里。
3. **扫描光带**：只有罗德岛保留常驻动效，12 秒从上到下扫过，`prefers-reduced-motion` 下关闭。

纹理层固定在 `z-index: 1` 且 `pointer-events: none`，不抢菜单、弹窗与用户点击。

## 七、终端界面层

`src/client/36-terminal-ui.js` 只做「结构标注 + 少量装饰节点」，颜色、边框、排版仍全部交给样式表。这样拆的原因是数据是运行时的：

- 工作区菜单是 portaled 的，只有打开时才存在；
- 侧栏列表会被应用反复重渲染；
- 工作区数量与当前选中项都不是静态 DOM。

伪元素拿不到这些数据，所以必须有一层幂等的 JS 扫描。

### 7.1 注入的节点

| 节点 | 位置 | 生命周期 |
| --- | --- | --- |
| `.ak-terminal-deck` | logo 行之后 | 侧栏存在时保持；文本随阵营更新 |
| `.ak-terminal-sector-head` | 工作区 `sectionHeader` 之前 | 跟随群组重渲染，每次扫描确认位置 |
| `.ak-sector-code` | 每个工作区行首 | 行被重渲染后补回；编号按当前顺序实时计算 |
| `.ak-terminal-footer` | `document.body`，仅空状态 | 有 hero 才创建，进入对话即移除 |
| `.ak-deploy-menu__head` | 菜单 viewport 顶部 | 完全跟随菜单生命周期，菜单关闭即消失 |

所有注入节点带 `.ak-*` 类和 `data-ak-tui` 标记；原生节点只加 `data-ak-tui` / `data-ak-sector` / `data-ak-active` 等属性，不改 class 与结构。

### 7.2 扫描范围与幂等

观察器只关注会改变终端结构的区域：

```text
[data-slot="sidebar"]
[data-slot="conversation.composer"]
[class*="_composerHero"]
[role="menu"]
```

流式输出会持续改消息 DOM，把它排除掉，观察器就不必为每个 token 排一次扫描。属性观察只过滤 `class` / `aria-expanded` / `aria-selected` / `aria-checked` / `aria-current` / `data-state`。扫描防抖 120ms；每个写入函数先比较再写入（`akSetText` / `akSetAttr`），重复执行不产生无谓的 DOM 变更。

关闭主题、切到通用适配或布局变化时，`destroyTerminalUI()` 会断开观察器、清除定时器、移除注入节点，并清掉所有 `data-ak-*` 属性，页面回到应用原样。

### 7.3 选中态：部署，不是展开

侧栏行的 `aria-expanded` 只代表目录展开。应用允许**同时展开好几个目录**；直接拿它当选中态，刚打开几个目录就会让整面墙一起翻成奶油色（真页面上七块板全亮、编号全翻黑牌，就是这么来的）。

当前逻辑：

1. 空状态存在时，读取 hero 中工作区选择器按钮的文本。
2. 按钮文本等于自身 `aria-label` → 还是占位文案，表示未选择；否则文本就是当前部署的工作区名。
3. 用这个名字与每个工作区行的标题比对，命中的行才标记 `data-ak-active="true"`。
4. 对话页没有 hero → 退回应用自身的选中信号（`_selected`、`_folderActive`、`aria-*` 等），`aria-expanded` 不在其中。
5. 用户在柜面上点过某一格 → 这一格优先于部署信号成为当前板。应用的点击只切换 `aria-expanded`、渲染会话，不会把工作区设为当前部署；主题在捕获阶段记下 `data-row-key`，下一轮扫描点亮它、把铭牌换成它，并只把**它那一组**的会话标成档案件。再点一次把它收起（`aria-expanded="false"`）→ 记下的 key 作废，当前板落回部署工作区。

`readDeployedWorkspace()` 的返回值有三种：`null`（没有 hero，走结构回退）、`''`（有 hero 但未选择）、工作区名（精确匹配）。这三种状态必须区分，否则会把「未选择」误判成「选了空名字」。

**名字放在 `data-ak-name` 上。** 36×108 的板面写不下工作区名，参考里名字也归一块独立的黑牌。当前板的名字钉在柜面正上方的铭牌（`.ak-terminal-sector-head__plate`）上；其余板悬停时，由 JS 在指针旁亮出一块 fixed 定位的 `.ak-sector-tip` 黑牌（右边放不下就翻到左边，上下夹回视口）。不能用 `title` 属性，原生 tooltip 会和这块牌叠在一起。

**柜面只排当前目录的会话。** DSH 会把所有展开目录的会话行都留在同一个列表里；主题只给当前板所在分组（从当前行往上找到的第一层「已经装着会话行」的祖先）的会话标 `data-ak-block`，其余组的会话行由 lab 层 `display: none`。否则读数会变成「BLOCK 01 / 05」，而用户点开的那组只占其中一段。搜索态没有工作区行时退回全部会话。展开后必须让会话真的落进柜面视口：柜面装得下就直接排；只有一行会话、柜面又矮时，会话块 sticky 到柜面底部形成托盘，并把当前板滚到托盘上方；多行会话时退回滚到会话区。应用的「展开其余 N 个会话」按钮也要标记成当前组末尾的窄操作带（`order: 3`），否则它按 order 0 排队，会把墙面切成 6 + 1 + 6 并撑出空行。

菜单项的选中态独立读取菜单自身的 class / `aria-checked` / `aria-selected` / `aria-current` / `data-state`；抬头上的扇区号取第一个选中项，没有选中时退回阵营默认扇区。

侧栏行的选择器是 `[data-row-key^="workspace:"]:not([data-row-key="workspace:"])`：空 key 是 DSH 给「未分组」会话桶的固定标记，它不是可部署工作区。排除它之后，抬头计数、行编号与菜单里的位置数才会一致。菜单抬头的位置数只统计 viewport 内的 `menuitem`，底部的「添加工作区…」不占部署位。

### 7.4 与阵营切换的衔接

阵营 class 翻转后，样式表已经换色。`akTerminalRepaint`（在 `35-faction-bar` 中声明并调用）只让终端层重跑一次扫描，把铭牌、频道、菜单抬头上的字标改成新阵营的文本，不重建节点，也不产生闪烁。

### 7.5 档位词表：同一块面板，两种说法

终端层的文本不写死在模板里，而是从 `TERMINAL_WORDS` 按 `readLayout()` 取一份：

| 槽位 | 进阶版 | 莱茵终端版 |
| --- | --- | --- |
| 铭牌品牌 | `PRTS` | `RHINE` |
| 铭牌副标 | `SECTOR / COMMAND` | `TRACK / SELECT` |
| 侧栏抬头 | `PRTS // DEPLOYMENT` · 终端作战位置 | `RHINE // LIBRARY` · 终端工作位置 |
| 抬头副标 | `TERMINAL DEPLOYMENT POSITION` | `WORKSPACE POSITION` |
| 读数标签 | `SECTOR` | `COLUMN` |
| 读数键位 | `↑ ↓ 浏览 · ENTER 部署` | `← → 换列 · ↑ ↓ 选块` |
| 档案板标签 | —（进阶版没有第二级） | `BLOCK` |
| 菜单抬头 | `PRTS // DEPLOYMENT CONTROL` | `RHINE // LIBRARY CONTROL` |
| 页脚通道 | `PRTS // OPERATIONS LEDGER` | `RHINE // PLAYBACK LEDGER` |
| 编号单位 | `SECTOR 01` / `12 SECTORS` | `TRACK 01` / `04 TRACKS` |

每个带 `data-ak-part="<槽位>"` 的节点在每次扫描时被重写（含 `<br>` 的那一份走 `innerHTML`，其余走 `textContent`，避免把 HTML 当字面量印出来）。所以切档位不需要重建 DOM，也不会留下上一档的措辞。

两档的词表**键集必须一致**——少一个键，切到那一档时对应的槽位就永远停在模板里的默认字面量上，而默认值是进阶版的。`check.js` 直接比对两档的键集合，多一个少一个都失败。（这条契约差点是假绿的：`String.match` 带 `/g` 返回的是整段匹配字符串、没有捕获组，`m[1]` 取到的是字符串的第 2 个字符，两边都会塌成同一堆垃圾字符并「相等」。取键名要用 `matchAll`。）

## 八、第三档：莱茵终端版（材质 + 结构层）

设计依据：[MikeQu223/Rhine-Music-Database](https://github.com/MikeQu223/Rhine-Music-Database)（Qt6/QML 音乐库终端）与它的演示视频 [BV1tTpq6kEiE](https://www.bilibili.com/video/BV1tTpq6kEiE)。它的界面不是「明日方舟的阵营皮肤」，而是一台**器材**：固定 1920×1080 舞台、整屏陶瓷白面板、立面是一组**文件柜**（见 8.4）、列表按行条纹、数值一律右对齐、标题是「一行大写拉丁 + 一行中文副标题」、返回键是实心块、全局只有一个圆形元素（播放盘），页脚写 `POWERED BY RHINE LAB`。

### 8.1 它叠在进阶版之上，不是第四套阵营

`lab.css` 的每条结构规则都同时挂着 `.theme-arknights-advanced.theme-arknights-lab`：少挂前者，它会去重排一个没有注入钩子的裸界面；少挂后者，档位切换找不到这一层。因此 `syncLayoutClass()` 在 lab 时把两个 class 一起加上，终端 DOM 层也照旧跑（`isTerminalLayout()` 对 advanced 与 lab 都返回真）。

### 8.2 分工：阵营管身份色，档位管材质

| 维度 | 令牌 | 归属 |
| --- | --- | --- |
| 谁的设备 | `--edge-accent` / `-accent-rgb` / `-accent-onpaper` / `--signal` / `--status-*` / 徽标形状 | 阵营（`faction.css`） |
| 哪一代器材 | 纸面家族、`panel/overlay/soft/line/line-2/ink/ink-2`、玻璃、字体字距、几何、装饰密度 | 档位（`lab.css`） |

档位**不覆盖强调色**，所以切阵营在陶瓷底上一样看得见；它另外重测了 `--edge-error/success/warn` 三个语义色——这三个是「写在陶瓷纸上」的角色，属于材质而不是身份。参考项目的两条硬规则被完整保留：一个界面里只允许一个圆形元素（给发送按钮，`advanced` 的斜切 `clip-path` 在这里退回直线），以及标签永远靠左、数值永远靠右、中间一根发丝线。

### 8.3 纸面为什么不是参考项目的那个色

参考的陶瓷底 `#e1ded6` 压在罗德岛钢蓝 `#1a6fa8` 上只有 4.02:1，过不了 AA。所以整套纸面家族上移一档到 `#edebe4`（暗色 `#141613`），逐对复测后才落库——**颜色是量出来的**这条规则在档位层同样成立。

### 8.4 两级选择：档案立面与短档案板

材质之外，这一档还搬来参考项目最核心的一处读法。演示视频里那台终端的立面是一组**文件柜**：一列列竖着的档案板排在近乎全黑的柜面上，每块板上部靠左贴一枚暖色小标签；当前那块被灯整块照亮、微微前移，板上钉一块黑牌。柜子是**平立面**——没有斜面、没有拉手、没有交叉纹理，这些是上一版自己加的，已经全部撤掉。DSH 的侧栏正好有同一批层级——工作区列表与会话列表——于是：

| 级 | DSH 对象 | 转法 | 读数 |
| --- | --- | --- | --- |
| 第一级 | 工作区行 `_projectRow` | 纵向清单 → 柜面上的竖档案板（36×108，一块平板，左上角暖色编号标签；当前板照成奶油纸白、前移 3px，标签翻成黑牌） | 抬头大读数 `COLUMN 01 / 13` + 键位芯片 + 柜面铭牌 |
| 第二级 | 会话行 `_sessionRow` | 纵向清单 → 同一柜面上的短档案板（86×74，标题两行截断，块号压在左上角标签上；当前板同样照亮、翻牌） | 柜面里 `BLOCK 01 / 02` |

几条实现约束，都是踩出来的：

- **柜面必须找到「装下全部行」的那一层。** 真页面里每行外面套着一层 per-item wrapper，几行又套一层分组；`akCabinetField()` 从第一行往上走，直到某个祖先真的包含本批全部行，再把沿途没有角色的 wrapper 全部摊成 `display: contents`。只取 `rows[0].parentElement` 会把柜面圈在第一组上——第一块板 36px，其余 251px 铺满侧栏，这就是真页面上那面「一整块白板」的来路。
- **同一个柜面装两级。** 工作区与会话住在同一棵树里；两个 pass 都把行摊平到同一层，用 `order` 排：工作区 0、读数带 1、会话 2。读数带是一条 `flex: 0 0 100%` 的伪元素，同时负责换行与「BLOCK xx / yy」；没有会话时属性缺席，伪元素不生成，柜面上不会留一条「BLOCK 01 / 00」。
- **柜体换行，纵向滚动。** 侧栏 270px，参考的舞台是 1920px。横向滚动会裁掉板面阴影，所以容器 `flex-flow: row wrap`，排满换行；应用把这一层高度钉死在侧栏里，板一多最后一行会被 region 的 `overflow: hidden` 裁掉，所以柜面自己 `overflow-y: auto`，并且 `scrollbar-gutter: stable` 固定留 6px——真页面默认滚动条 17px，一出现就把六列挤成五列。`check.js` 禁止 lab 层出现 `overflow-x: auto`，并要求恰好一处 `row wrap`。
- **空桶行必须收掉。** 应用会在工作区行之外挂一条 `data-row-key="workspace:"` 的「未分组会话」折叠头（251×34）。它不是可部署工作区；不单独标注并隐藏，它就是柜面上一块横贯整行的板。
- **铭牌在抬头，不在柜面。** 36px 的板面放不下工作区名。参考把名字钉在一块黑牌上；这里把它钉在柜面正上方整行宽的位置——终端层注入的 `.ak-terminal-sector-head__plate`（`data-ak-part="plate"`），lab 画成黑底暖白字，进阶版用 `faction.css` 收掉。它曾经试图做成 `sectionHeader::after`，但那个抬头是柜面列表的**兄弟节点**且只有 36px 高，伪元素在结构上永远命不中。其余板的名字写在 `data-ak-name` 上，悬停时由 `.ak-sector-tip` 在指针旁亮出一块同材质黑牌；36px 板面本身仍然只有编号。
- **点开一格 = 打开一个抽屉。** 应用点击只改 `aria-expanded`、渲染会话，不改变部署工作区。主题在捕获阶段记下 `data-row-key`，扫描时把这一格当成当前板：点亮、换铭牌、只排它那一组的会话；再点一次（`aria-expanded="false"`）就作废，落回部署工作区。这条「浏览态」与 `aria-expanded` 无关，因此同时展开多个目录时也只有一块当前板。
- **柜面只排当前组的会话。** 展开多个目录时，DSH 会把各组会话都渲染进同一个列表。主题从当前行往上找第一层装着会话的祖先，只给这一组标 `data-ak-block`；其余组的会话行留在 DOM 里，由 lab 层 `display: none`，否则读数会变成「BLOCK 01 / 05」而用户点开的那组只占一段。展开后必须让会话进入柜面视口：柜面装得下就直接排；只有一行、且柜面高度不足时，把会话块 sticky 到柜面底部当托盘，当前板滚到托盘上方；多行时退回滚到会话区。摊平后的柜面里，应用的「展开其余 N 个会话」按钮也会参与排版，必须标成当前组末尾的窄操作带（`order: 3`），否则它按 order 0 排队会把墙面切成 6 + 1 + 6。会话行挂的原生悬停预览卡固定落在侧栏左上角，会盖住抬头，lab 档把它收起，块内截断的标题改用 `title` 兜底。
- **选中 = 被灯照亮，不是换成强调色。** 参考里选中的那一列只是照得更亮，柜体没有因此变蓝。所以亮板读 `--lab-lit-slab`（暗档奶油 `#f0e2bd`、亮档 `#fffdf6`），纸上的字读 `--lab-lit-ink`（两档都是深墨）——`--edge-paper` 是「页面底色」，在暗档里是黑的，不能拿来当亮纸上的字。强调色仍归阵营，只出现在铭牌左边线与控件上。
- **标签有两个反转。** 未选中板的标签是一枚黄铜/暖金小牌（`--lab-tab`），选中板的标签翻成黑牌（`--lab-plaque`），字一律 `--lab-plaque-ink`。两处都要 `!important`：通用令牌层给选中行后代写了 `color: #000 !important`，会话板的 `::after` 一度漏了这一条，暗档里就是黑牌黑字，真页面上「01」整块消失。
- **柜体要站在应用的整页纹理之上。** 应用在 `body::before` 上铺了一层 `position: fixed; z-index: 4` 的点阵 + 六边形水印，侧栏在它下面，于是柜面浮着点阵、水印穿过板面。lab 给侧栏根节点 `z-index: 5`（faction 已给它 `position: relative`），柜体成为实物，页面其余区域保留应用底纹。
- **`flex-direction` 对非 flex 容器也返回 `row`**（初始值），几何断言必须先判 `display`，否则进阶版的纵向清单会被误判成横排。

`node test/shoot.js` 因此不只比颜色：它量档案板是不是竖长（`h > w` 且 `h ≥ 90`）、短档案板是不是横长（`w > h` 且 `h ≥ 60`）、柜面在 lab 下是不是真的横排换行、读数是不是 `01/05` 这种两位比、键位提示有没有按档位换词；lab 档另加几条专治「静默失效」——柜面收拢了全部工作区板且确实摊平了 wrapper、会话板落在同一柜面上、铭牌取到了字、铭牌与标签牌的文字对底色都到 4.5:1、柜面 `scrollWidth - clientWidth` 不超过 1px。fixture 里另外留了两组同样带 `aria-expanded="true"` 的目录，用来卡住「整面墙一起点亮」的回归：每块板必须有 `data-ak-name`、当前板恰好一块、铭牌与当前板同名、别的目录的会话全部 `display: none`。`test/verify-real.js` 在真页面上再走一遍：把视口锁到 1366×768，用真实鼠标逐个点开折叠目录，直到找到一个真正渲染出会话的目录，断言会话块落进柜面视口（单行托盘时当前板也仍可见）、读数带与块数一致，再点一次回到部署工作区。

## 九、可读性修正

几何层之外，还有一组随主题自动生效的修正，处理「装饰语言」与「应用原生控件」的接缝：

- **预览徽标**：切角实心强调底 + 纸色字，覆盖基类里写死的深色前景；莱茵亮色的近黑底因此不会出现黑字压黑底。
- **新会话按钮**：实心强调底上的文字、图标与悬停态一律用 `var(--edge-paper)`，不在四个位置各写一个 `#000`。
- **顶栏模式胶囊**（「标准模式」等）：去掉原生浅底，改成实心强调底 + 纸色字与图标；悬停态保持同一组变量。
- **审批弹窗**：重绘为全屏白条式确认区，主次按钮用实心 / 描边区分；禁用态降低透明度而不是改色。
- **回合状态标签**：读 `--edge-status-*`，扫光亮带经过字形时两种底色都过 AA。
- **选中、光标、滚动条**：统一读强调色；滚动条在“圆角模式”下仍保持细窄，不出现系统默认的宽条。

这些修正都不改变控件尺寸与点击区域，只改视觉。

## 十、边界与经验

如果只带走几句话：

1. **颜色是量出来的，不是挑出来的。** 每个色值都对它实际落在的表面算过对比度；不达标的写法（哪怕看起来「就该是这个颜色」）一律改掉。
2. **同一个色在亮/暗模式下往往需要相反的处理。** 亮色下沉、暗色提亮，取决于该色相在那个亮度还剩多少余量；当前亮色档直接选用了通过 AA 的深档，暗色档才使用明亮强调色。
3. **「装饰」和「前景」用两套标准。** 前景守 AA / AAA；装饰守「不抢眼但可见」的区间（约 1.12–1.6:1）。
4. **主题令牌自身可以是 `var()` 引用。** 这是把「换配色」从一次重绘降级成一次 class 切换的关键。
5. **底色归主题、文字归应用 = 裂缝。** 只接管背景令牌而不接管前景，会造出「白字压在黄底上」这类不可读组合。改一个背景令牌时，要一起检查谁在上面写字。
6. **运行时数据要有幂等的标注层，而不是伪元素。** 菜单、动态列表与选中项只能由 JS 标注；标注必须可重复、可收回，扫描范围要避开流式输出。
